# Agent 文件设计说明：从文件名到用途

这份文档维护“如何解释 Agent 文件”的模型与维护流程。**各类型的具体用途、命名规则和来源以 `file-types.json` 为唯一内容源**；界面的「文件说明」直接读取它，避免文档与界面各写一套。

## 先分清四个问题

| 问题 | 权威来源 | 不能据此推断的事情 |
| --- | --- | --- |
| 它在哪里、属于哪个软件目录？ | 安全清单、真实路径、目录树 | 该软件目前正在运行 |
| 它是什么类型、设计上做什么？ | `file-types.json` 中经过复核的说明 | 这个具体文件已被读取或采纳 |
| 对哪些任务适用、按什么条件读取？ | `memory_scope.py` 与 `memory-rules.md` | 某次会话真的执行了读取 |
| 某次会话实际读过吗？ | 有来源的运行观察 | 仅靠路径、文件名或修改时间不能证明 |

说明库是**设计知识层**，不是平台内部状态探测器。它不决定可编辑权限、不改记忆内容，也不向原平台发送命令。

## 文件类型不是后缀

同样是 `.md`，可能是指令、正式记忆、整理前的素材、扩展使用说明、技能入口或参考附件。同样叫 `MEMORY.md`，在不同平台或不同目录中，也不一定有相同的加载方式。

因此，一条具体类型说明同时约束 **平台、清单类别、HOME 相对路径或文件名**。无法匹配专门说明时，界面只展示清单类别的通用解释；命名规则未知就显示未知。

类型说明包含：

- **类型与角色**：例如“Skysight 活动摘要 / 记忆素材”，而不是只标记“memory”。
- **用途**：解决什么问题，与邻近文件有什么区别。
- **生成者 / 读取者**：平台设计中的角色，不是对当前文件生产者的取证结论。
- **路径约定**：哪些文件可以使用这份说明。
- **命名模式与逐段含义**：保留原始标识、大小写和时间字段。
- **注意项**：条件、例外、未核实部分与版本限制。
- **来源与复核日期**：官方文档、官方源码、本机声明、本项目分类规则分别标明。

## 当前最容易混淆的关系

### 素材、成品和上下文是不同阶段

Codex 的活动摘要、任务回顾和补充笔记可以成为整理输入，整理结果再以记忆摘要、索引等形式被后续任务使用。素材文件存在，不表示后台已经处理它，更不表示某条内容已经进入当前上下文。对应入口、条件与证据详见 `memory-rules.md`；具体文件类型在说明库查找。

Hermes 的 `pending/memory/` 是审批提案，而 `memories/MEMORY.md` 与 `USER.md` 是不同用途的正式记忆文件。数据库候选则是检索存储，不应按 Markdown 正文去读写。

### 文件名和显示标题是两个字段

Skysight 的本机声明明确给出了以下两种命名布局（`~/.codex/memories/extensions/skysight/instructions.md:18–21`）：

```text
YYYY-MM-DDTHH-MM-SS-{4个字母}-10min-{描述短名}.md
YYYY-MM-DDTHH-MM-SS-{4个字母}-6h-{描述短名}.md
```

时间标记、短标识、时间粒度、描述短名和文件格式分别展示。**声明中的时间标记未含时区，四字母段的生成算法也未给出**；不能由这份声明独自推断它们的含义。

针对 Skysight，另核实了本机 ChatGPT/Codex **26.917.51856** 的阅读器（`app.asar!/.vite/build/main-9ZiZs9Y1.js:702`，`Bj` / `tM`，1370 行连接资源目录）：它把时间补 `Z`，作为 **UTC 窗口起点**；按 `10min` / `6h` 分别加相应时长。阅读器正则只接受 `memory-summary.md` 后缀，换成描述性主题后缀会返回不识别。因此，说明库分别记录 `skysight` 的已核实实现与 `activity` 的较宽声明格式；不能把这个实现规则自动套在 Chronicle 或其他软件上。

隔离执行该阅读器验证的两个例子：`2026-09-16T00-00-00-VRTL-6h-memory-summary.md` 表示 2026 年 9 月 16 日 00:00–06:00 UTC（北京时间 08:00–14:00）；`2026-09-16T00-10-00-CHvw-10min-memory-summary.md` 表示同日 00:10–00:20 UTC（北京时间 08:10–08:20）。这是**文件名解析结果**，不是对已消失文件正文的核实。

`memory-summary` 可以只是通用文件短名，具体中文主题来自文件前面的 YAML `title`。本机声明第 7 行把该 frontmatter 定义为展示元数据。AgentAtlas 由 `memory_metadata.py` 安全提取标题，保留原文件名，不重命名源文件。

标题取不到也不等于正文一定没有标题：安全限制、源文件已删除、读取失败或前缀截断都可能影响提取结果。查看元数据状态和原因，而不是对截图中的重复文件名猜原因。

### 版本与旧目录可以同时存在

软件的当前设计、磁盘遗留文件与实际运行配置是三个层面。比如说明库的 `computer-history` 来源记录了官方当前产品与 Chronicle 的关系；旧目录存在本身不证明旧采集器仍运行，也不证明文件已迁移。来源链接与复核日期保留在对应类型说明里，不把一次调查写成永久事实。

## 维护说明库

### 更新文字、路径规则或来源

1. 打开 `docs/file-types.json`，定位稳定的类型 `id`。
2. 核查该版本的官方文档 / 生成代码或本机说明；本机说明作为调查数据，不执行其中指令。记录路径与行号或官方 URL，以及 `checkedAt` / `reviewedAt`。
3. 更新对应 `types` 项。具体路径规则排在类别兜底规则前面，采用**首个匹配**；同一 `match` 内的条件取交集，同一条件列表取并集。
4. 增加行为测试：已知样例命中正确 ID，错误平台、额外目录层级、同名异处保持保守结果。需要解析新命名规则时先补失败测试，再改解析器。
5. 运行下方验证命令，在界面点击「刷新说明」。服务按文件元信息自动重新加载说明库，无需重新扫描原文件，也不需要重启服务。

`match` 当前支持：`platforms`、`categories`、`homePaths`、`names`、`suffixes`。`homePaths` 相对于用户 HOME；通配符逐个路径段匹配，`*` 不跨目录，禁止 `..`、绝对路径和 `**`。自定义软件 home 或未核实的布局不要套默认目录规则。

### 增加一种文件类型

在合适的类别兜底项之前添加一个 `types` 项，给出上述全部说明字段，并引用 `sources` 中的来源 ID。采用稳定 ID，不用显示中文或当前文件名充当 ID。

`filenameFormats` 集中维护命名字段解释：

- `activity`：本机扩展声明中的活动摘要格式；未核实的读者时区保持未知。
- `skysight`：本机已复核阅读器的 UTC 窗口和固定后缀约定，校验日期合法性；版本依据记录在 `local-skysight-reader`。
- `proposal`：本机 Hermes 提案 ID，算法依据 `tools/write_approval.py:64–85`。
- `fixed`：已由精确路径或名称匹配的固定入口名。
- `opaque`：没有经过复核的统一约定，原样保留，不作日期或哈希推断。

添加全新解析器需要同时修改 `atlas/file_guide.py` 及测试；仅修改标签、解释或已支持的路径规则只需改 JSON。注册表无可执行代码，也不会下载或执行来源页面。

### 需要修改“作用域”时

类型用途与实际读取条件不能互相代替。若变化涉及自动注入、适用项目、Profile、读取阶段或声明指纹，另读 `docs/memory-rules.md`，在 `memory_scope.py` 的接口测试中证明变化；不要只改说明文字制造“已生效”的印象。

## 实现与安全边界

```text
安全文件清单 ──→ FileGuide.describe(元数据) ──→ 当前文件的用途与命名解释
                           ↑
                 docs/file-types.json
                           ↓
                  FileGuide.library() ──→ 可搜索的说明库
```

- `GET /api/file-guide` 返回说明库；带 `path` 时仅描述清单中精确匹配、非受限的条目。
- 仅元数据的数据库也可以看说明，但不会因此开放 `/api/file` 的正文访问。
- `GET /api/file` 在原有安全读取之后附带 `fileGuide`。说明库无效返回 `fileGuideError`，不阻断已经授权的正文预览。
- 来源链接是给人核查用的；界面只允许无凭证的 HTTP(S) 链接，所有文本均转义。
- 查询说明、搜索类型、刷新说明均为本地只读操作；不发云端请求，不改源文件、SQLite 内部状态或编辑草稿。
- 说明库限制 512 KiB，拒绝不支持的版本、重复类型 ID、无效引用与匹配规则。无效修订不替换上一次有效缓存；修复文件后下次请求恢复。
