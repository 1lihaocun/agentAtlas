一句话总览 —— 把 Codex 的记忆想象成一条中央厨房流水线

你每次和 Codex 聊天都在「点菜」；后台把吃过的菜做成原料（各种摘要），再统一炒成一锅（两个成品记忆文件），下次开新会话时自动端上来。

① 三个来源 （同时进行，互不相干）

你 ↔ Codex 的聊天会话日志
每次对话完整录下来，存为会话日志。英文叫 rollout＝一次会话/任务的完整记录。它本身不是记忆，是记忆的原材料。
两个后台常驻进程记忆素材
Skysight（内部代号，无官方译名）：汇总你电脑上的活动事件流；Chronicle（内部代号）：被动录屏。它们按 10 分钟/6 小时切片生成「活动摘要」，跟聊天无关，一直在录。
你的明确要求记忆素材
你说「记住 XX」时，模型才会当场写一张「补充/纠正笔记」（ad-hoc＝临时、专门为此写的）。它不能直接改记忆成品，只能塞纸条。
│ 聊天会话结束后空闲满几小时，后台才会动手 ↓

② 两级后台加工 （都不占用聊天，模型聊天时自己碰不到）

第一阶段：逐会话提取stage1＝第一道工序
每个会话日志 → 生成一份「会话/任务回顾」（rollout summary，角色=会话摘要）＋一份「初步提取的记忆汇总」（raw＝没加工的毛料，角色=整理输入）。
第二阶段：全局整理consolidate＝合并整理
把所有原料倒进一口锅：会话回顾＋初步提取＋Skysight/Chronicle 活动摘要＋补充笔记 → 炒出两个成品。
加工说明书处理规则
「记忆扩展使用说明」（每个扩展目录里的 instructions.md）是写给整理流程看的：哪些素材该怎么用、打什么标签。它不是记忆内容，是规则。
│ 整理完成 ↓

③ 两个成品 （整理后的记忆，只有这两个）

记忆总览 memory_summary.md成品·自动注入
招牌拼盘，每桌必上：新会话一打开就被截断塞进提示词，不管你问什么都带着。
记忆索引与经验 MEMORY.md成品·按需翻查
后厨大仓库：全文长得多，模型按关键词去搜（grep），搜到哪条用哪条。
│ 下次新会话开始 ↓ （循环回到①）

④ 回到聊天 —— 闭环

记忆总览自动出现在开场提示词里；不够用时模型再去记忆索引里搜；引用了哪条还会在回复末尾生成引用标注（citation＝出处标注），并给该条记一次「被使用」——被引用多的记忆更不容易被后台清掉。

英文词对照

原文意思
rollout一次会话/任务的完整记录（日志，不是记忆）
stage1 / phase1第一道工序：逐会话提取摘要
consolidate / phase2（consolidation＝整理合并）第二道工序：全局合并所有原料成两个成品
raw（raw memories）毛料/未加工的提取结果
ad-hoc（note）临时、专为此事写的（补充笔记）
Skysight / Chronicle两个后台感知功能的内部代号（活动事件流 / 被动录屏），官方无中文名
summary（memory summary）摘要/总览
inject（injected into prompt）注入＝自动塞进开场提示词
grep按关键词全文搜索
citation出处标注（回复末尾注明用了哪条记忆）

注：Skysight / Chronicle 是产品内部代号，官方文档未给中文名；其余术语均按含义翻译。两张成品图（总览、索引）每次被后台整理任务重写，你手动改它们没用——下一轮整理会覆盖；想补记忆应该写「补充笔记」，AgentAtlas 的来源徽标会告诉你每份文件具体是哪条流水线产的。
